A library, represented as a semantic network

Books, members, staff and authors are nodes. Borrowing, authorship and publishing are labelled links. Ask the network a question and it answers by following those links.

Reasoning

Nothing is stored twice. Answers are worked out by moving through the network.

  1. Start at a nodeFor example, the individual Alice.
  2. Climb the linksAlice is-a Student, Student is-a Member, Member is-a Entity.
  3. Nearest value winsA specific class overrides a general one, so Faculty gets 30 loan days instead of the Member default of 14.

Design notes

Scope: a university library where borrowing rules depend on the type of member and the type of book.

RepresentationStrengthFit for this project
Semantic networkVisual, natural for hierarchies and relations, inheritance for freeChosen: the domain is a graph of concepts
FramesStructured slots with defaults and proceduresClose cousin; properties here behave like slots
First-order logicPrecise semantics, quantifiers, negationMore power than the library rules need
OWL ontologyFormal, standard, automated reasonersGood next step for larger catalogues

What it demonstrates

  • Transitive is-a closure
  • Property inheritance with overriding
  • A rule that combines several facts into one decision

Limitations

  • Link meanings are informal, with no formal semantics
  • No general negation, quantifiers or uncertainty
  • Single inheritance only, so conflicts between parents are not handled
